# Car vs Tape — BACKEND (game server)

Frontend (3D client) lives at `../Car-vs-tape`. Colyseus + Mongo, ported from the Bowling Roll server and reduced to what Car vs Tape saves.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, pfp, loadout })`). Client-authoritative: the server only bounds/sanitises saves (`src/sanitize.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- Signed-in players' progress lives in this server's Mongo doc; guests / no-server play keep progress for the page only (client `src/net.js`; no browser save).
- Messages client -> server: `saveProgress` (the whole `game.snapshot()`, every 5 s when changed), `identify` (`{ userId, username, pfp }` after a sign-in/out mid-session), `pose` `{ x, y, z, yaw, speed (signed), steer, thr, flags }` (~10/s; flags: braking 1, drifting 2, handbrake 4, treadmill 8, boosted 16, stunned 32, rocket 64 = Shift boost burning, flying 128 = FLY thrusters on), `loadout` `{ car, level }`, `emote` `{ kind }` (1 cheer, 2 wave, 3 honk), `avatar` `{ equipped, proportions, skin }` (also in the join options; skin only from Bloxity hosts), `playActive` `{ active }` (tab shown/hidden), `claimChest`, `claimCar` `{ car }`. Server -> client (private): `progress` (saved doc, sanitized), `noProgress` (new account, guest, no database: the client keeps its state and saves it), `serverError` (save unreadable: saving stays off), `leaderboard`, `playtime` / `chestResult` / `carResult` (playtime rewards, below). Saves are ignored until the session's load answered (`loaded`). A second live session on the same account is evicted.
- Saved shape (`PlayerDoc`, client `game.js` `snapshot()`): `power`, `wins`, `totalWins`, `level`, `xp`, `rebirths`, `owned[]` (car ids, always includes `pebble`), `car` (equipped, must be owned), `bestTape` (-1 = none), `boostUntil` (epoch ms; `boostReadyAt` is legacy), `lastSeen`. Server-only fields (never taken from a save, not in `progress`): `playMs`, `chestClaims`, `carPlayMs`, `carGifts`, `giftedCars` (merged back into `owned` on every load). `bestTape` and `totalWins` are written with `$max` so a stale save never lowers them.
- Roster (`PlayerState`): `username`, `signedIn`, `pfp` (http(s) only), `x/y/z/yaw/speed/steer/thr/flags`, `car`, `level`, `emote`/`emoteN`, `uid` (signed-in Bloxity id, matches chat senders), `avatar`/`props`/`skin`. Relayed only (bounded in `presence.ts`); the client draws other players in `src/remotes.js`.
- Leaderboards (`src/leaderboard.ts`): the plaza's three boards, `LEADERBOARD_STATS` = `power`, `wins`, `rebirths`. `leaderboard` { boards: { stat: [{ name, value }] }, ranks: { stat: n | null } } after each load and every `LEADERBOARD_EVERY_MS`.
- `src/constants.ts` bounds must cover the client's `src/config.js` (CARS ids match `ID_PATTERN`; `DEFAULT_CAR`; `TAPES_MAX` >= `TRACK.tapes.length`). A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev). Needs repo var/secret `LEGION_GAME_ID` (= `car-vs-tape`) and secret `LEGION_DEPLOY_TOKEN`.
- Boxity (`src/bloxity.ts`, `test/Bloxity.test.ts`): needs hosting's `BLOXITY_REPORT_TOKEN`, `BLOXITY_GAME_ID`, `BLOXITY_API_URL` (no-op without token/id). After each `saveProgress` the player's values are queued and sent every `REPORT_EVERY_MS` (batches of 200, Boxity accounts only: `legion_<id>`, never `guest-`/`dev-`): leaderboard boards `power`/`wins`/`rebirths` (`BOARDS`, mode best) and profile stats (`STATS`: level, rebirths, tapes_snapped, wins, total_wins, power; values over Boxity's per-type limits are skipped). Client message `adReward` { rewardToken } -> `adRewardResult` { ok }: Boxity verifies the single-use rewarded-ad token (`/v1/ads/reward/verify`) before the client grants the boost.
- Playtime rewards (`src/playtime.ts` `PlayRewards`, `test/Chest.test.ts`): signed-in sessions (non-guest id) get two `PlayClock`s from their doc once the save loads: the Free Boost chest (`playMs`, goal `playRewardMs()` = 1 h, env `PLAY_REWARD_MS`) and the free car (`carPlayMs`, goal `carGiftMs(gifts)` = 30 min x (1 + 0.5 x gifts), at most 2 h, env `CAR_GIFT_MS` sets the base). They run while connected and `playActive`, stop on a dropped connection until the reconnect, cap at their goal, and are saved with each `saveProgress`, on leave, on identity switch and every `PLAY_SAVE_EVERY_MS`; an evicted session's clocks carry over. `playtime` { signedIn, active, playMs, needMs, claims, car: { playMs, needMs, gifts, gifted[] } } after each load. `claimChest` -> `chestResult` { ok, reason?: signin | loading | early, ...playtime }; the client pays the Wins + boost. `claimCar` { car } (the client's pick: `CAR_GIFT.jump` tiers above its best) -> `carResult` { ok, carId, reason?: signin | loading | early | owned | bad, ...playtime }; ok adds the id to `giftedCars` and `$addToSet owned`, and the next goal is longer.

- Room directory (`src/legion-room-reporter.ts`, `installRoomReporter()` in `src/index.ts`): every 2 s POSTs this pod's rooms to `${MATCHMAKER_REPORT_URL}/${BLOXITY_GAME_ID}/rooms` (Bearer `BLOXITY_REPORT_TOKEN`) so Boxity's game-page "Open Rooms" and join-by-id work. No-op without those env vars (hosting injects them).
